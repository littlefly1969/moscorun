# C7 — Ciclo di vita scientifico

- Lock transazionale PostgreSQL per atleta, applicato a tutti gli scrittori scientifici. Erasure atomica delle osservazioni, feedback, chunk, checkpoint, registry e run; fence durabile blocca nuovi import fino a ripristino esplicito. Non cancella le tabelle legacy di allenamenti/pesate o l'account.
- Retention esplicita con preview e conferma: query ricorsiva server-side conserva tutti gli antenati delle osservazioni e dei run/feedback trattenuti; cancella chunk scaduti e modelli inutilizzati, mantiene checkpoint per evitare reinvio indiscriminato. Nessuna scadenza automatica imposta. Un connettore che reimporta dati scaduti deve rispettare la policy retention del chiamante.
- Export JSON Lines v1 su stream seekable vuoto e a blocchi, owner-scoped, coerente rispetto agli scrittori scientifici tramite lock. Include metadati nativi, note, segnali, artefatti e audit; esclude il valore dei token cursore. Il chiamante deve proteggere il file e non esporlo senza autenticazione.
- Audit durabile di export, retention, erase e resume, senza contenuti fisiologici. ID operazione idempotente per mutazioni; una richiesta export nuova usa un nuovo ID. L'audit segue l'account e non è un registro legale immutabile indipendente.
- Conferma, autenticazione, autorizzazione e programmazione della retention rimangono nel livello applicativo; nessun endpoint o cancellazione reale è effettuato da questa PR. I backup hanno un proprio ciclo di retention/ripristino; non equivale a cancellazione completa GDPR dell'account.
